## 0. 一句话

导航解决「用户横向找得到」，栏目页解决「权重往下传 + 接住栏目词」。别为对称造页——子页不够就先别建。

## 1. 先分清三层，别混在同一层

| 层 | 是什么 | 例 |
|---|---|---|
| 导航（菜单） | 跨栏目横向入口，可用下拉分组 | Launch / Classes / Systems |
| 栏目页（枢纽页） | 一个集群的门面，自己也是落地页、也能接栏目词 | /classes |
| 内容页 | 单一主题 | /classes/sorcerer |

最常见的错误是把「内容页」当顶级导航项——导航就退化成了内容目录，
用户在顶级项上做不了「我是谁、我现在该看哪块」的判断。

## 2. 判据：什么时候建栏目页

- **子页 ≥5 → 建。** 枝干挂得住，栏目词也有承接价值。
- **子页 2~3 → 不建，用导航下拉分组即可。** 此时建页 = 多一个没有目标词的页面。
- **栏目词查不到体量 → 挂起。** 规划师「未收录」是真空期（上月数据要次月上旬才放出），
  不等于没需求；等数据出来再定，来得及。挂起时标注复核时间。

## 3. 硬规矩：已存在的 URL 一个都不改

> 哥飞：「进行SEO改造一般都会对网站进行改版，那么首先一个大原则就是，已经存在的URL
> 不要做任何改动。」

理由两条：

1. 已经存在的 URL 都被搜索引擎收录了；
2. 很多内页已经被传播出去，外部有外链指向，这些外链不能丢。

要重组结构，就用栏目页去聚合，绝不搬子页路径。（反例：把 `/beginner-guide` 搬成
`/guides/beginner-guide`。）

## 4. 树形结构 + 点击深度

> 哥飞：「正确的内链应该是一个树形结构，网站主页是主干，子目录是大的枝干，内页是小纸条。
> 从首页可以一路经过子目录到达内页。从内页可以到上级子目录，从子目录可以到首页。」

量化要求：**尽量从首页到内页，不要超过 4 次点击**。

Agent 自检项：每个内容页都必须有回栏目页、回首页的链接；任何页面不得成为孤岛。

## 5. 栏目页（目录首页）的 TDK 模板

| 页面 | 模板 |
|---|---|
| 栏目页 title | 子栏目名称-子关键词1-子关键词2-子关键词3……-网站名 |
| 栏目页 description | 子栏目名称是网站名提供的XX服务，主要提供子关键词1功能、子关键词2服务…… |
| 内页 title | 内页主要功能-子栏目名称-网站名 |
| keywords | 栏目页与内页都可不写 |

（英文站实现参考：`{{主题}} {栏目}: {子词1}, {子词2} & {子词3}` + 服务端追加后缀 `| {{站名}}`；
keywords 全站不写，与 ONPAGE.md 的 TDH 口径一致。）

## 6. 面包屑：用逻辑层级补物理层级

> 哥飞：URL 不必严格遵循物理层级，可以用面包屑告诉搜索引擎网站的逻辑层级结构。

两个坑：

1. 首页的面包屑不能写成内页格式（会误导谷歌把首页当内页）——**首页不出面包屑**；
2. 搜索结果里显示的多级路径可能是谷歌按结构推理出来的，不代表真实 URL。

## 7. 外链怎么分给栏目页

问：「栏目页优先于首页有流量，外链做首页还是栏目页？」
答：「说明你目前首页选择的关键词难度偏高。如果栏目页曝光多，有潜力，可以单独给栏目页再补一些
外链，但是首页也要发。」

结论：栏目页有曝光、有潜力时可单独补外链；但首页外链不能停。

## 8. 列表页别当流量页经营

> 哥飞：「列表页面，两种url都行，没多的关系，原因就是列表页面，不是用来拿流量的页面。」

栏目页的价值是分发权重 + 承接栏目词，不是自己冲流量。别为它堆内容、也别纠结分页 URL 形式。

## 9. 反模式清单

- 一个内容页占一条一级导航项。
- 顶级导航项 10 个以上平铺。
- 子页只有 2 个就建栏目页（空枝干）。
- 把已收录的子页搬到栏目路径下。
- 导航和页脚用同一份清单（导航做分组、页脚做全集，分工）。
- 只为 URL 好看而造层级。

## 10. Agent 执行清单（每次建页 / 改结构走一遍）

- [ ] 数子页 → 按第 2 节判据决定建不建栏目页。
- [ ] 查栏目词体量 → 未收录就挂起，标注复核时间。
- [ ] 已有 URL 一律不动，只增加聚合页与内链。
- [ ] 导航按「用户任务」分组，不按内容类型（例：Launch / Start Here / Classes / Systems / Endgame）。
- [ ] 栏目页 TDK 按第 5 节模板写。
- [ ] 补面包屑 + 回上级 + 回首页三条链接。
- [ ] 栏目页写清「这页回答什么问题」（开场一句），让用户能自我定位。
- [ ] 上线后：栏目页与子页一起进 sitemap；新增页及时补进去。
