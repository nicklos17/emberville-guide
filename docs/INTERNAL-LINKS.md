# 内链规范（内链.md v1.1）

## 0. 怎么用这份文件
写新页面、改旧页面、做完部署后，跑第 11 节的自检清单。任何一条不过就是内链缺陷，不需要再问。
v1.1 增补（导航搭好之后生效）：栏目横向互链、面包屑、页脚完整站点地图、栏目页关键词。

## 1. 层级模型（本站固定 4 层）
- L0 首页 `/`
- L1 栏目页：参考 `SITE.md`
- L1 一级内容页：Launch 组（early-access / countdown / founders-pack / download / servers / player-count / twitch-drops）、Start Here 组（beginner-guide / leveling-guide / free-to-play）、tier-list、factions、progression、flight、crafting、dungeons、pvp
- L2 子页：`/classes/*`（8 个）、`/builds/*`（8 个）、`/pets/*`（5 个）、`/tools/*`（3 个）
- 规则：**L2 可以链接到 L0/L1/L2；L1 不得放进导航组里当子项**（导航只放 L0 + L1）

## 2. 每种页面的链接义务（硬性）
| 页面类型 | 必须向下链 | 必须向上链 | 正文内链下限 |
|---|---|---|---|
| L0 首页 | 每个 L1 枢纽各 1 条（8 个板块 H2 里至少 3 处带链接） | — | 6 |
| L1 枢纽页 | **其下所有 L2 子页，一个不漏** | 首页 1 条 | 子页数 + 2 |
| L1 内容页 | 相关 L1/L2 各 1–2 条 | 首页 1 条（页脚兜住即可）+ **相关枢纽 1 条（必须正文内链）** | 3 |
| L2 子页 | 同层兄弟页 1–2 条 | **所属枢纽页 1 条 + 首页 1 条** | 4 |

所有页面都必须有一条指向首页的内链。

横向规则（与上表并行，硬性）：
1. **同级栏目页互相横向链**（Guides ↔ Wiki ↔ Crafting 式）：枢纽 ↔ 枢纽、内容页 ↔ 内容页、枢纽 ↔ 相关内容页均可。
2. 每个 L1 页正文至少 **2 条**指向同级栏目的内链，计入正文内链下限。
3. 横向锚文本带目标栏目词（例：`our {{主题}} crafting hub`），不裸链单词栏目名。

## 3. 面包屑（每页必配，面包屑本身就是内链）
1. 除首页外每个页面必须有面包屑，路径从首页写全：`Home / Crafting / {{某配方}}`。
2. 每一级都是 `<a>` 内链，仅最后一节（当前页）是纯文本。
3. 层级：L1 页两级（Home / 页面），L2 子页三级（Home / 枢纽 / 子页）；**首页不出面包屑**（`栏目.md` §6：防止首页被当成内页）。
4. 配 BreadcrumbList 结构化数据——URL 不必是物理层级，用面包屑把逻辑层级喂给谷歌。
5. 面包屑与导航同类，**不计入**正文内链下限。

## 4. 锚文本规则
1. 锚文本必须是**描述性的**，含目标页的主题词（例：`AION 2 event timer`、`the Spacetime Rift schedule`）。
2. 禁用：`click here`、`read more`、`this page`、`here`——一律不算内链。
3. **同一页内、指向同一目标，只链一次**（首次出现处）；后文提及时用纯文本，不再加链接。
4. 正文锚文本避开与导航完全相同的短词（导航已用 `Tier List`，正文用 `our AION 2 tier list`）。
5. 英文页面锚文本用目标页的**主关键词原形**，不要用中文或缩写。

## 5. 每页的固定三件套（写完必查）
1. 一条指回**所属枢纽页**
2. 一条指回**首页**（或在页脚统一兜住）
3. 一至两条指**同层兄弟页**（比"相关文章"更有用的形式是：句子里的自然引用，如 `…is covered on our AION 2 PvP page`）

## 6. 页面尾部 Related 区规范
- 每页正文下方保留 `Related AION 2 coverage` 区，3–5 条，**每条必须是 `<a>`，不是纯文本**
- 该区链接目标**不得与本节上方正文重复**
- 该区**计入**第 2 节的"正文内链下限"

## 7. 页脚规范 = 全站站点地图（当前不合规，待改）
现状：18 条 = About / Contact / Privacy / Terms / Disclaimer / Search / RSS / Sitemap（全为法务与功能页）

改成：页脚当**完整站点地图**用，分三栏——
1. **内容栏：所有 L1 页面全集**（枢纽 + 一级内容页，不挑选）
2. **信息栏：未进导航的信息页**（系统配置 / 价格 / 成就类）一律从这里接入，不留孤岛
3. 法务与功能页照旧

分工与 `栏目.md` §9 一致：**导航做分组，页脚做全集**，两份清单不许相同。
L2 子页不进页脚（枢纽页已全链，20+ 条会撑爆页脚）。
理由：哥飞 3 群原话——「不要让网页成为孤岛页面，任意页面都有回到首页和其他主要页面的链接」。
预期收益：改一处，全站每一页多出全集入口，未进导航的页面全部被兜住。

## 8. 栏目页不是纯列表（栏目词与内页同待遇）
1. 栏目页要打**栏目主词**：title / H1 / 首段必须含（例：`/crafting` 打 `{{主题}} crafting`），与内页一个待遇。
2. 首段一句话写清「这页回答什么问题」，再进链接区——不许开场就是裸列表。
3. 栏目词先在 `KEYWORDS.md` 登记，TDH 按 `ONPAGE.md` 与 `栏目.md` §5 模板执行。
4. 边界（`栏目.md` §8）：栏目页承接栏目词 + 分发权重，但不为它堆内容冲流量——开场段 + 分组导语 + 链接区，够用即止。

## 9. 禁则（不要做）
1. **不为凑数堆链接**：一页正文内链超过 15 条即视为过度，删到 15 以内
2. **不删导出链接（Source 行）**：指向 SteamDB / Questlog / Game8 的链接是"可信赖性"证据，保留且**不加 nofollow**
3. **不给同一目标在同一页出现两次链接**（导航、页脚、面包屑除外）
4. **不在导航里塞 L2 子页**：子页只走枢纽页正文（本站当前就是这个设计，保持）
5. **不改已上线 URL 路径**：内链调整只改 href，不动 slug
