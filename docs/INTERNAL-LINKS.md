## 1. 层级模型（本站固定 3 层）
- **L0 首页** `/`
- **L1 栏目页**：8 个核心栏目`/wiki`、`/guides`、`/release-date`、`/platforms`、`/map`、`/builds`、
  `/characters`、`/news`（定义见 `SITE.md`）
- **L1 从属页**：`/item-database`（Wiki 附属）、`/price`（Release 附属）——层级等同 L1，
  但主词让给父栏目，不独立承接栏目词（`/countdown` 已于 2026-10-10 撤页，不设 301）
- **L1 专题页**：`/voice-cast`、`/studio`、`/stardew-valley-diablo`、`/games-like-emberville`——
  从栏目页拆出的独立搜索需求，层级等同 L1，**不进导航**，靠首页与相关栏目页正文内链进入
- **L2 栏目子页**：`/platforms/multiplayer`（Platforms 附属）——不进导航，由 `/platforms` 正文内链进入
- **L2 详情页**：`/{hub}/{slug}`（按 `KEYWORDS.md` L3 表逐页登记；当前已上线 `/news/emberville-demo`，游戏内具体条目仍须有可核验数据后再开）
- 规则：**导航只放 L0 + L1**，L2 子页不进导航（见第 9 节禁则 4）

## 2. 每种页面的链接义务（硬性）
| 页面类型 | 必须向下链 | 必须向上链 | 正文内链下限 |
|---|---|---|---|
| L0 首页 | 每个 L1 栏目各 1 条（板块卡片 + 正文内链合计覆盖 8 个栏目） | — | 6 |
| L1 栏目页 | **其下所有已登记 L2 子页，一个不漏** | 首页 1 条 | 子页数 + 2 |
| L1 从属页 | 父栏目的 1 条（`/item-database` → `/wiki`；`/price` → `/release-date`） | **父栏目 1 条（必须正文内链）** | 3 |
| L1 专题页 | 相关栏目页 1–2 条 | **所属栏目页 1 条（必须正文内链）** | 3 |
| L2 栏目子页（`/platforms/multiplayer`） | 同层兄弟页 1–2 条（如存在；没有真实兄弟页时不虚构） | **所属栏目页 `/platforms` 1 条** | 3 |
| L2 详情页 | 同层兄弟页 1–2 条（如存在；没有真实兄弟页时不虚构） | **所属栏目页 1 条 + 首页 1 条** | 4 |

所有页面都必须有一条指向首页的内链（页脚 Logo + 首页兜住）。

横向规则（与上表并行，硬性）：
1. **同级栏目页互相横向链**（Wiki ↔ Builds ↔ Map 式）：栏目 ↔ 栏目、内容页 ↔ 内容页、
   栏目 ↔ 从属页均可。
2. 每个 L1 页正文至少 **2 条**指向同级栏目的内链，计入正文内链下限。
3. 横向锚文本带目标栏目词（例：`our Emberville builds hub`），不裸链单词栏目名。

## 3. 面包屑（每页必配，面包屑本身就是内链）
1. 除首页外每个页面必须有面包屑，路径从首页写全：`Home / Map / Emberville Map`。
2. 每一级都是 `<a>` 内链，仅最后一节（当前页）是纯文本。
3. 层级：L1 页两级（Home / 页面），L2 子页三级（Home / 栏目 / 子页）；**首页不出面包屑**（`栏目.md` §6：防止首页被当成内页）。
4. 配 BreadcrumbList 结构化数据——URL 不必是物理层级，用面包屑把逻辑层级喂给谷歌。
5. 面包屑与导航同类，**不计入**正文内链下限。

## 4. 锚文本规则
1. 锚文本必须是**描述性的**，含目标页的主题词（例：`Emberville build hub`、`the Emberville map regions`）。
2. 禁用：`click here`、`read more`、`this page`、`here`——一律不算内链。
3. **同一页内、指向同一目标，只链一次**（首次出现处）；后文提及时用纯文本，不再加链接。
4. 正文锚文本避开与导航完全相同的短词（导航已用 `Builds`，正文用 `our Emberville builds guide`）。
5. 英文页面锚文本用目标页的**主关键词原形**，不要用中文或缩写。

## 5. 每页的固定三件套（写完必查）
1. 一条指回**所属栏目页**
2. 一条指回**首页**（或在页脚统一兜住）
3. 一至两条指**同层兄弟页**（比"相关文章"更有用的形式是：句子里的自然引用，如
   `…is covered on our Emberville characters page`）

## 6. 页面尾部 Related 区规范
- 每页正文下方保留 `Related Emberville coverage` 区，3–5 条，**每条必须是 `<a>`，不是纯文本**
- 该区链接目标**不得与本节上方正文重复**
- 该区**计入**第 2 节的"正文内链下限"

## 7. 页脚规范 = 全站站点地图（已落地）
页脚当**完整站点地图**用，分三栏：
1. **内容栏：所有 L1 页面全集**（8 栏目 + 2 从属页 + 专题页，不挑选）
2. **信息栏：法务、功能与来源页**（About / Sources & Methodology / Contact / Privacy / Terms）
3. `src/content/navigation.json` 的 `footerLinks` 是唯一来源，改一处全站生效

分工：导航做核心入口（顶部 9 项 = 8 栏目 + Items 从属页），页脚做全集（16 项），两份清单不完全相同。
理由：哥飞3 群原话——「不要让网页成为孤岛页面，任意页面都有回到首页和其他主要页面的链接」。
L2 子页将来不进页脚（栏目页已全链，20+ 条会撑爆页脚）。

## 8. 栏目页不是纯列表（栏目词与内页同待遇）
1. 栏目页要打**栏目主词**：title / H1 / 首段必须含（例：`/map` 打 `Emberville map`），与内页一个待遇。
2. 首段一句话写清「这页回答什么问题」，再进链接区——不许开场就是裸列表。
3. 栏目词先在 `KEYWORDS.md` 登记，TDH 按 `ONPAGE.md` 与 `栏目.md` §5 模板执行。
4. 边界（`栏目.md` §8）：栏目页承接栏目词 + 分发权重，但不为它堆内容冲流量——开场段 + 分组导语 + 链接区，够用即止。

## 9. 禁则（不要做）
1. **不为凑数堆链接**：一页正文内链超过 15 条即视为过度，删到 15 以内
2. **不删导出链接（Source 行）**：指向 Steam 商店页 / SteamDB 的链接是"可信赖性"证据，保留且**不加 nofollow**
3. **不给同一目标在同一页出现两次链接**（导航、页脚、面包屑除外）
4. **不在导航里塞 L2 子页**：子页只走枢纽页正文（本站当前就是这个设计，保持）
5. **不改已上线 URL 路径**：内链调整只改 href，不动 slug（`栏目.md` §3）。
   唯一例外是撤页（`/countdown`，2026-10-10 人工决策，直接删页不设 301）——
   这类操作须记入 `docs/CONFLICTS.md`；其余情况一律禁改
