# ONPAGE.md — 页面优化规则（TDH 写法）

> 依据：哥飞《从 TDK 到 TDH》(2024-04-06)、《养网站防老第5步：内页和内链建设》(2024-08-12)、
> 《从网站站内优化到部署上线再到推广运营》(2024-08-13)。
> 本文件是 AGENT.md 第 5 节（页面骨架规则）的展开细则。冲突时以 AGENT.md 为准。
> 栏目页（枢纽页）的建页判据、URL 禁改与栏目 TDK 模板另见 `栏目.md`；
> 写内容前先确认该页属哪一层（导航 / 栏目页 / 内容页）。
> 内链的具体义务（层级模型、各页型链接义务、锚文本、Related 区、页脚、禁则）以 `INTERNAL-LINKS.md`
> 为准，写页/改页时必须遵守，发布前跑其第 9 节自检清单。

## 0. 核心口径：TDH，不是 TDK

- 不再写 `keywords` meta 标签。哥飞原话：**"早在10年前，哥飞就不写 Keywords 了"**、
  **"keywords 关键词列表，一般可以不写。我的优化风格是优化不要太满"**。
- 三要素是 **T（Title）+ D（Description）+ H（Headings）**。
- 哥飞原话：**"一个网页的 Headings 就相当于这个网页的骨架，是用来支撑整个网页内容的骨骼结构的。
  用好 TD和H，才能够做好网页优化。也是拿到关键词在谷歌搜索排名的关键。"**
- 每个页面**开工前先确定一个核心词**，全页的 T / H1 / H2 都围绕它展开。不要一个页面打两个词。

## 1. T — Title 规则

### 1.1 为什么重要
哥飞原话：**"这是搜索引擎判断一个网页的主要内容最重要的参考来源之一。很多时候我们说SEO优化，
其实就是如何写好网页标题。"**

### 1.2 写法（5 条硬规则）
1. **核心关键词放最前**，不要放在品牌名后面
2. **长度 50–60 字符**
3. **拼装法**：把"用户可能会关心的、且有搜索流量的"修饰词拼上去。
   哥飞原话：**"如'学爸主演、演员表、主角、评分、票房'。用户可能会关心的，且有搜索流量的，
   都可以拼凑上去。"**
   → 落到本站：日期 + 实体名 + 类别 + 数据 + 更新日期，都是可拼装的修饰词，
   **但每个都必须真实可搜**，不许瞎拼。
4. **时效页带年份/月份**（release date / tier list / patch notes / codes）
5. **品牌后缀只加内页**，首页不加（首页 60 字符预算要全给关键词）

### 1.3 常见反例
| 反例 | 问题 | 改法 |
|---|---|---|
| `{{主题}} Release Date, Early Access & Guide` | 缺年份，时效页无时间信号 | `{{主题}} Release Date 2026: Early Access & Launch` |
| 404 页复用首页 Title | 404 页无独立 TD | 给 404 页独立 TD，保留 noindex |
| 无登记先写 Title | 主词冲突/遗漏 | 每个新页面必须先在 `docs/KEYWORDS.md` 登记核心词，再写 Title |

### 1.4 一词一页的让位机制
详情页上线即占用其词形（如 `{实体} build`），父页 Title 不得再用同词形措辞，
否则父子互抢同一个词。

- 机制：父页数据加可选 `seoTitle` 覆盖，父页 `[slug]` 模板按 `item.seoTitle ?? 默认模板` 渲染
- 同步面：指向该页的内链 `title` 属性经映射镜像新 Title
  （站内约定：内链 title 镜像目标页完整 SEO title）
- **详情页每次上线，回头检查对应父页 Title 是否需要让位**（AGENT.md §7 固定规则）
- 词形取舍：保留规划里有量的词形；规划未收录的连写变体果断弃用——
  拆写保主词（`{{主题}} X Build (PvE)` 而非 `{{主题}} X PvE Build`），超线但关键的年份词可沿先例超限

## 2. D — Description 规则

哥飞原话：**"description 网页描述，也比较重要，也会出现在搜索结果中。"**

- 长度 **120–155 字符**，不截断
- 必须含核心词（自然出现一次即可，不重复堆砌）
- **写"用户点进来能拿到什么"，不写"本页介绍了……"**
- 一类不该做的事：**不要把 Title 原样复述**。哥飞用豆瓣举例时指出，豆瓣是
  **"把一些本来要写到标题里的，写到描述里去了"**——Title 装不下的修饰词下放到 Description。
- 每页 Description 必须唯一。禁止模板批量生成（`... for {{受众}} players` 这种尾巴）。

## 3. H — Headings 规则（写作技巧的核心，AI 写作必读）

### 3.1 H1
- **一个页面只能有一个 H1。** 哥飞原话：**"一个网页只能有一个h1"**
- 哥飞对 T 与 H1 的分工：**"如果说 title 是给搜索引擎看的，那么 h1 就是给用户看的。
  但同时搜索引擎也会参考 h1 来对你的网页进行内容评判，最终给不给你排名，排在哪个位置，
  很多时候就是 h1 和 title 决定的。"**
- 所以：**H1 与 Title 措辞必须不同**（一个偏自然语言、一个偏关键词堆叠），但都含核心词。
- **H1 里必须出现核心关键词，且尽量靠前。**
- ❌ 反例：问句式 H1（`When does X launch?`）把页面主轴钉在一个长尾问句上，核心词被稀释。
  问句需求交给 H2 或 FAQ 承接。
- ✅ 改法：名词短语，如 `{{主题}} Global Launch — Release Date and Early Access`

### 3.2 H2 / H3
- **每一个 H2 都必须是关键词表里的一个真实可搜的词**，不是编辑自拟的标题。
  哥飞的做法：从关键词工具导出内页相关词 → 交给 AI → **"每一个 section 都是一个 h2"**。
- H2 之间**层级并列、不交叉**；H3 挂在 H2 下面细分。
- **禁止**用 `Introduction` / `Overview` / `Conclusion` / `Why This Matters`
  这类零搜索价值、零信息量的空话标题。
- ✅ H2 示范（栏目页）：`{{主题}} Classes and Roles` · `{{主题}} Class Tier List` ·
  `{{主题}} Class Builds` · `Which Class Should You Main` · `{{主题}} Classes FAQ`

### 3.3 典型网页结构（照这个搭，不要自由发挥）
```
h1
h2
p
h3
p
h3
p
h2
p
h3
```

配套规则（同样出自哥飞）：
- **p 装正文**，图片也放在 p 里
- **img 必须写 alt**：**"img 标签一定要写 alt 属性，这是对图片的描述，专门写给搜索引擎看的。"**
- **图片用大图**：哥飞原话 **"图片尽量用大图，也就是300x300以上的"**
  → 高价值图片（图标、地图、截图）的 **alt 写清"是什么"**，不要写"{{主题}} image"

## 4. 写作技巧（约束 AI 的正面清单）

### 4.1 每条硬规则
1. **H2 不许自创**：必须来自 `docs/KEYWORDS.md` 或其拓词结果。写不出对应的词就不写这个 section。
2. **每段必须有信息增量**：可验证的事实、数字、具体名称（实体名 / 名称 / 日期）。
   一整段如果只由形容词构成，删掉。
3. **一个事实只说一次**。同一页内不许在正文和 FAQ 里重复同一个答案。
   **重复的 FAQ 是负资产**——换成正文没答过的问题。
4. **模糊量词一律禁止**：`many players` / `generally` / `often` / `it is said that` /
   `most people` → 要么给具体来源，要么不写。
5. **没有来源就不写"官方"**。凡是标 `Official` 的数据块，来源必须真的是第一方页面，并逐项核对。
6. **段落长度 ≤ 4 行**；超过就拆成 H3 或改列表/表格。
7. **能表格化的就表格化**。对比、分档、数值——表格 > 散文。
   （竞品教训：排名页只给字母、不给理由、不给表格的，就是可击败的靶子。）
8. **不写"本文将会介绍/综上所述"**。直接进内容。
9. **时效页必须带日期戳**：`Updated: YYYY-MM-DD · <版本号>`，与 `dateModified` 一致。
10. **语言只用 en**，不生成多语言版本，不加 hreflang（AGENT.md §2）。

### 4.2 AI 生成后的验收问法（每次都要过）
对每个新页面问自己三个问题，有一个答不上就重写：
1. 这页的 H2 分别对应哪个真实搜索词？
2. 这页有什么是竞品页面上没有的（数据、深度、日期、来源）？
3. 页面里有没有任何一句是没有来源的事实性断言？

### 4.3 禁止项（对齐 AGENT.md §1 / §6）
- ❌ 编造名称、数值、日期、排名
- ❌ 无实测就给评级（一律标 `Pending launch`）
- ❌ 拿旧服/旧版数据冒充新版结论（必须标口径，如 `Based on KR/TW builds`）
- ❌ 复制第三方站点正文
- ❌ 把第三方营销页当事实来源

## 5. 内链建设

### 5.1 层级与关键词的对应关系（哥飞原话）
> **"主关键词用域名首页来做，二级关键词用子目录来做，三级关键词用子目录的子目录来做，
> 最后是内页。"**

| 层级 | 关键词例 | 页面 |
|---|---|---|
| 主词 | {{主题}} | `/` |
| 二级 | {{主题}} categories | `/categories`（栏目页） |
| 三级 | {{主题}} category item build | `/builds/{item}` |
| 内页 | 长尾 | `/wiki/{item}`、`/dungeons/{name}` |

### 5.2 内链的定义（哥飞原话）
> **"内链建设的意思是，既要能够从首页有链接到每个二级、三级关键词，也要每个页面都有链接
> 能够指向到上级。"**

拆成三向，缺一不可：

| 方向 | 规则 | 落法 |
|---|---|---|
| 首页 → 下级 | 首页必须链到每个二级、三级页面 | 首页分类网格**必须是真的 `<a>`**，不能是纯文字 |
| 下级 → 上级 | 每个页面都要有链回上级 | 面包屑：首页 → `/categories` → `/categories/{item}` |
| 全站 → 首页 | 所有页面都有指向首页的链接 | Logo + 面包屑首节 |

### 5.3 一个内页配两个锚文本变体（哥飞的具体手法）
哥飞的实操是：给每个内页在首页放 **2 个链接、传 2 个不同关键词**。
> 原话：**"这样我们首页就给每个国家的内页都增加了2个链接，分别传递了'xxx Phone Number
> Generator'、'Generate xxx Phone Number'两个关键词的权重到对应的国家内页。"**

落到本站（以 `/categories/{item}` 为例）：
- 锚文本 1：`{{主题}} {Item}`
- 锚文本 2：`{Item} guide`

**且要给 `<a>` 加 `title` 属性**——哥飞原文里首页 h1、导航、列表的每个 a 标签都加了 title。

### 5.4 首页「六字真言：分门别类罗列」
哥飞原话：**"哥飞总结了首页可以用的六字真言：分门别类罗列。"**

他给的首页结构就是**按类别分 H2、类别下罗列 H3 + 列表/图片**：
```
h1 {{主题}}
h2 {{主题}} Classes → N 个 H3（各链到详情页），每项 2 个锚文本
h2 {{主题}} Builds → 各 build 页
h2 {{主题}} Dungeons → …
h2 {{主题}} Tier List
h2 {{主题}} Patch Notes
```

### 5.5 内链红线
- ❌ **不准有孤岛页**。"说了要链却不链"的句子必须补成真链接，或删掉那句话。
- ❌ **锚文本必须与目标页主词同词形**——build 词锚全部指向 build 系页面，不得锚向类页
  （父页让位后尤其注意，防词形经锚文本或 title 属性回流）。
- ❌ 锚文本不许用 `click here` / `read more` / `learn more`，必须是目标页的核心词。
- ❌ 不许为了凑内链给无关页面加链接（相关性 > 数量）。
- ✅ 每页正文内 **3–5 条**兄弟或下行链接。
- ✅ 父页只写总览与对照表，**不写完整的子页内容**（父子页自相竞争要特别防——
  `/categories` 与 `/categories/{item}` 天然重叠）。

## 6. 后端渲染与 URL 唯一（不可协商）

哥飞原话：
> **"以上所有这些都需要直接在 html 代码里体现出来，而不能是前端渲染。也就是说，我们打开网页，
> 浏览器右键查看网页源代码，需要能够看到这些内容。"**
> **"虽然，的确搜索引擎有时候能够解析前端js，触发渲染。但这需要更多的算力资源，凭什么给我们的
> 新网站用。所以新网站，老老实实后端渲染。"**

- 内容页必须 **SSR**：T / H1 / 正文 / 内链 / JSON-LD 全在初始 HTML 里
- 验收动作：**禁用 JS 后刷新，页面正文必须可见**（AGENT.md §3）
- **URL 唯一**：一个页面可能有多个 URL 可达（www / 非 www、http / https、带尾斜杠 / 不带），
  必须用 `canonical` 指定唯一规范 URL。
- 开站即定：canonical 用**无尾斜杠绝对路径**（`trailingSlash: false`），www → apex 走 301。
  **定了不许改**，改了会产生重复内容。

## 7. 发布前自检清单（每页必过）

- [ ] 核心词已在 `docs/KEYWORDS.md` 登记，且全站唯一
- [ ] Title 50–60 字符，核心词在开头，时效页带年份
- [ ] Description 120–155 字符，未复述 Title，全站唯一
- [ ] **有且仅有一个 H1**，含核心词，与 Title 措辞不同
- [ ] 每个 H2 都对应一个真实搜索词，无 `Introduction` 类空话标题
- [ ] 结构符合 h1 → h2 → p → h3 → p
- [ ] 所有 img 有 alt，且图片 ≥ 300x300
- [ ] 正文 ≥ 1200 字符，含至少一张表格或数据块
- [ ] 每个数据块带来源与 `Verified` 日期；标 `Official` 的真的是第一方来源
- [ ] 页面内无重复事实（正文答过的，FAQ 不再答）
- [ ] 无 `many players` / `generally` / `it is said` 类模糊表述
- [ ] 首页 → 本页有链接（且 ≥2 个锚文本变体）
- [ ] 本页 → 上级有链接（面包屑）
- [ ] 本页 → 首页有链接
- [ ] 正文内 3–5 条兄弟/下行链接，锚文本是目标词
- [ ] 已逐条通过 `docs/INTERNAL-LINKS.md` 第 9 节内链自检清单
- [ ] 已写 `title` 属性的 a 标签
- [ ] 禁用 JS 后正文可见
- [ ] canonical 为无尾斜杠绝对路径
- [ ] 显示 `Updated: YYYY-MM-DD`，与 `dateModified` 一致
- [ ] 已在 `docs/CHANGELOG.md` 记一行
- [ ] **跨页口径一致**：本页的承诺句与姊妹页现状不矛盾——父页 Pending 行不得列详情页已交付项
- [ ] **新内容上线时 grep 全站旧结论句**：新页面交付某内容后，其他页面"还没发布/谁发谁在猜"
      类旧句子会变成自相矛盾，当日必修
- [ ] **数字变量语义与渲染标签一致**：对数 ≠ 个数——计数变量先换算再渲染
- [ ] **og:image 有值**：自有分享图或 `DEFAULT_OG_IMAGE` 回退，1200×630（SEO.md 分享图节）
